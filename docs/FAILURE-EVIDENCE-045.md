# Held X4 0.1.45 failure-evidence candidate

This local candidate keeps the frozen 0.1.44 image intact. It selects Runtime 0.1.93 at `148ad226b55db00e1dc451f21f11696f2b77f0a5` and Home 0.3.19 at `b95850b5a4b1979ce16116102a4ee1877980c506`. All other app/provider store bytes, the nineteen resident foregrounds, original GameBoy 1.3.22, boot policy, namespaces and grants are preserved. The only changed store paths are `default.elf`, `default.json` and `cohort.json`.

`minimal/scripts/resident_native.py` prepares the DIO80/dio_opi native composition. The explicit `failure_evidence` selection adds the recorder define, panic-wrapper link and forced ABI marker, and compiler stack-usage output. Staging and product admission both rerun Runtime's pinned ELF/BIN audit. This validates the actual panic call chain and IRAM closure, internal-DRAM state, 1,280-byte RTC object, ELF identity embedded in the firmware descriptor, stack report, and actual RTC budget. Bootloader, partition and initial AppData hashes remain frozen; startup source and rollback/brownout/octal80 PSRAM settings remain unchanged.

Build the native source at its recorded clean checkpoint, then stage it with `prepare_native_runtime.py stage`. Build the full image through `minimal/scripts/package_failure_evidence.py`; pass the frozen .44 baseline, pinned Runtime and Home source/target, native candidate and native-source checkpoint, and pinned packaging-tools source. `minimal/apps/failure-evidence-cohort.json` binds all input hashes. Packaging independently reads the baseline SPIFFS from its full BIN, compacts only Home with code/data/relocation identity checks, admits all 44 ELFs with the final native ELF, rebuilds SPIFFS, and verifies exact final full-image and preserved-region readback.

Generic native provider policy remains empty and unselected. Runtime .94 host/resource changes and stopped .87 USB-exit work are excluded. No cold-boot power policy changes, publishing, delivery or flashing are performed. Host tests and target linking do not qualify physical panic/reset/retention/display behavior. Retention is conditional on reset and power domain, backtrace is bounded to eight validated internal-SRAM frames, and there is no relocated-app symbolication or complete SDK panic-stack guarantee. Existing USB/MSC and manual low-power limitations remain.
